# PAUL phase 14 — Gameplay Recovery (SEED / Game Design Lab)

**Baseline**: `ba8e5251c58479fb6d9080d7525c3785b0f79003` (2026-11-19). **Mode**: development branch; preserve `main`.
**Intent**: implement five recovery themes without turning the repo into a different game or claiming unperformed human playtests.

## Decisions and alternatives
- **DECIDED**: remain 11v11, single-player, one manually controlled player, physical ball, 120 Hz fixed step. No multiplayer, no career expansion.
- **DECIDED**: experimental top/bottom wall rails instead of throw-ins; goal line/corners/goal kicks continue.
- **DECIDED**: directional human passing and visible failure feedback; no magnetic possession, no guided human movement.
- **ASSUMED**: reduce physical body radii moderately while preserving 5v5 legacy regression fixtures.
- **DECIDED**: opt-in automated coach updates during recovery mode, preserving all roles/tactics behind existing APIs.
- **ALTERNATIVE — NOT IMPLEMENTED**: realistic foosball, a separate design candidate with fixed rods, lateral sliding, rotational angular momentum, banking, timing and skill-based match play; requires isolated vertical-slice test before pivot.

## PLAN / acceptance gates
### Task 1 — Fix player agency and ball behaviour
Files: `main.lua`, `src/sim.lua`, `src/passing.lua`, `src/view.lua`, `tests/`.
- AC1: Human directional input selects a viable target inside an aim cone; none aligned yields an aimed space pass rather than a nearest-mate surprise. No input uses last heading.
- AC2: A rejected pass has visible feedback; buffering may allow a pending action on nearby contact within a short bounded window; no pass executes after restart.
- AC3: Smaller collision sizes do not break kickoff, goals or physical pass planning, including both 5v5 and 11v11.

### Task 2 — Stable AI and reversible tactics
Files: `src/ai.lua`, `src/sim.lua`, `main.lua`, `tests/`.
- AC4: Support-player positional requests have deadband/hysteresis, without impairing pressers, receives or kick planning.
- AC5: Coach switches are disabled by default in the recovery baseline and can be enabled explicitly in the running game for an A/B playtest; no roles/settings removed.

### Task 3 — Restore requested boundaries and validate
Files: `src/sim.lua`, boundary tests, documentation.
- AC6: top/bottom rails bounce ball and never award throw-ins, while left/right goal-line exits continue to produce correct scores/corners/goal kicks.
- AC7: all runnable unit/integration suites pass in CI on a PR; test evidence is accurately stated, human UAT remains NOT_RUN.

## Game Design Lab evidence gate
Hypothesis: participants can deliberately aim 10 passes, receive and advance the ball, and observe predictable AI positioning before tactics proliferate.
Observation: count aimed vs unexpected passes, contact failures, trapped/stationary ball episodes, back-and-forth press switching and resets. Run baseline and recovery versions with the same scenario.
Decision: retain 11v11 if core interactions become readable; otherwise compare against a separate realistic-foosball greybox (one human rod and automated opponent) before pivoting.
