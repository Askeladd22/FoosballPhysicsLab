## PLAN / SEED
**Observed:** prior `MeshArt` contains only 2D PNGs and the camera is an affine 2D shear. The supplied `Table_Soccer.zip` really contains OBJ groups `TS_Main`, `TS_Field`, `TS_Ball`, and all **eight separated** colored goalkeeper/defence/midfield/attack rods; 18 score-counter groups also present. OBJ is Y-up, length along Z, rod axis along X, in cm. Author's README explicitly says OBJ loses pivot/translation setup; reconstruct pivots around Y=83.2, center Z for each rod.
**DECIDED:** user-local offline **OBJ→GPU binary mesh** converter built in Python stdlib, no Blender/Pillow/third-party runtime. LÖVE 11.5 **newMesh with float3 positions, normals, vertex RGBA** + shader with real perspective, depth test, directional lighting and dynamic per-rod rotation/translation. Reuse original geometry, not the 201 sprites.
**DECIDED:** original `model.lua` remains authoritative physics and receives all 8 rod transform updates and 3D ball position each frame; 3D must not drift into an invented separate football game. Override camera with a genuinely elevated perspective view when meshes are present, P toggles source geometry 3D vs readable classic 2D. The old affine/sprite modes are not the main display.
**DECIDED:** no original/converted model binary committed: ZIP README by Hend Z. / VERTX3D grants commercial/noncommercial use but forbids redistribution in whole or part. Convert strictly on owner's computer; supply the owner their private transformed archive separately without public publication.
**ASSUMED:** world mapping of author coordinates (X width, Y up, Z length) can visually line up with existing prototype's 1000×560 field and the rod X positions via centered local pivots. It is not physical CAD tolerances.
**UNVERIFIED:** actual Love renderer, shader compatibility, FPS and precise foot collision alignment until native run / visual UAT.

## Acceptance criteria
- **AC1** real OBJ meshes: static frame/field/counters + eight independent movable rod rigs + ball loaded via GPU mesh buffers, never a frame-sprite crossfade. Renderer can verify exact group asset paths and inputs.
- **AC2** perspective camera with depth buffer, lighting, preserved physics and mouse-controlled rod sliding / rotation, score and ball movement. P switches 3D/2D without resetting score. Render still works in procedural 2D when local assets absent.
- **AC3** converter is read-only against owner's ZIP, produces only ignored local assets with attribution manifest, can self-test on synthetic OBJ and verify actual uploaded ZIP; no proprietary binaries in PR.
- **AC4** Lua 5.4/LuaJIT unit tests and independent frozen NEON11 suite remain green; native LÖVE GPU smoke via synthetic geometry is attempted and reported honestly.
- **AC5** native user UAT: screenshot from real 3D, 10 deliberate swipes, match ball/rod positions and FPS. Must not declare successful visual gameplay just from unit tests.

## Game Design Lab stop rule
If real 3D obscures the ball, changes perceived accuracy or lags, keep a 2D fallback and fix camera/rig transforms first. Do not add career/online/new match systems.
