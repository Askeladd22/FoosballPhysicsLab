# PAUL 22-01 — Repository split: Foosball in root, NEON 11 isolated under legacy

**Baseline:** `7fc46da1f9a806f73364c829321992160eeac077` (main, FoosballPhysicsLab).
**Branch:** `refactor/foosball-root-neon11-legacy`.
**Approved request:** move all 11vs11-specific code into a legacy folder and promote Foosball to the main/root folder, without removing either game, third-party source rights, or regression tests.

## PLAN (PAUL) / SEED decisions
**DECIDED:** Foosball becomes a direct root LÖVE application: `main.lua`, `model.lua`, `layout.lua`, `theme.lua`, `mesh_art.lua`, `rod_selector.lua`, `conf.lua`; root Foosball tests remain in `tests/`. Default `love .` opens Foosball with no `experiments/foosball` import indirection.
**DECIDED:** move entire `src/` to `legacy/neon11/src/`, legacy-only tests to `legacy/neon11/tests/`, their asset `assets/etrusco_unico.png` to `legacy/neon11/assets/`, historical documents/scripts and old physics lab there. Leave original legacy test/source file *blobs unchanged*; run them from `legacy/neon11` working directory. `love legacy/neon11` must launch frozen NEON11.
**DECIDED:** continue supporting `love . --legacy` from repo root with a tiny boot path and an explicit module search prefix; preserve prior user command where possible.
**DECIDED:** move old 11vs11 PAUL project/roadmap and phases (1–14, 16-eleven-flow) under legacy; root PAUL becomes Foosball-specific and retains its history.
**DECIDED:** external Table Soccer mesh derivatives remain **untracked** under root `local_assets/` and former ignored `experiments/foosball/local_assets/` is recognized for migration; no binary assets are published.

**ASSUMED:** running legacy from its own folder preserves `require("src.*")` and original image paths without changing frozen gameplay source. Verified by CLI regression tests, native LÖVE still requires user inspection.
**OPEN:** the quality of AUTO rod switching and third-party model permission; out of scope for a directory-only migration.

## Acceptance criteria
- **AC1:** all active Foosball entry and logic files live in root, no `experiments/foosball` module imports left in tracked source; `love .` loads direct Foosball. Root tests use `require("model")` etc.
- **AC2:** every original legacy module/test and its ball texture remains bitwise identical, but relocates to `legacy/neon11/`; `love legacy/neon11` runs with LÖVE 11.5, `love . --legacy` remains an optional shortcut.
- **AC3:** docs, planning and original PAUL phases correctly partitioned; no leftover 11vs11 source, tests or FM24 tooling in active root. Git history unchanged and frozen project not deleted.
- **AC4:** CI Foosball and legacy test suites are independent and green on Lua5.4 and LuaJIT, covering full previous regressions and smoke paths; no original models introduced.
- **AC5:** native LÖVE Foosball, root-legacy and standalone-legacy launch smoke UAT explicitly recorded as NOT_RUN until tested on Windows.

## Game Design Lab reality check
This is an architecture/clarity change, **not a gameplay improvement**. No claims of better physics, AI or fun. Measure correctness by boot behavior, independently passing suites, and whether a new contributor can find the active game in the root without confusion. **Stop rule:** if any legacy test breaks, fix routing/environment only, not frozen 11vs11 simulation logic.
